# 工作区发现、选择与原地续做

选择已有目录后，AuToDo 在原目录执行任务。新工作区位于当前项目的 `workspaces` 下。

## 三种模式

| 模式 | 执行目录 | 验收目录 |
| --- | --- | --- |
| 默认 | 每次运行的 `runs/<时间>/workspace` | 同一独立目录 |
| 新建 | `workspaces/<agent>/<名称>--ws-<唯一标识>/project` | 本次 `runs/<时间>/workspace` 快照 |
| 已有 | 从目录列表选择的原目录 | 新建运行记录下的 `workspace` 快照 |

通过浏览器选中目录不会写入它。服务端在派工和实际启动前重新验证目录与占用状态，仅接受目录列表的稳定 ID，不接受请求中任意绝对路径。实际执行器、模型、思考强度和工作区绑定写入运行记录。执行完成后先运行配置的检查，再复制快照并由 Codex 独立验收，最后仍等待本人复审。

## 自动读取的来源

| Agent | 本地路径索引 |
| --- | --- |
| Codex | `.codex/.codex-global-state.json` 的保存工作区根目录 |
| DSH | `.dsh/storages/workspace.json` 的工作区路径字段 |
| ZCode | `.zcode/v2/tasks-index.sqlite` 的未删除项目根目录 |
| Qoder | 应用主数据库中的未删除、未归档工作区路径 |
| Antigravity | 暂仅派工台历史与配置仓库；未确认可用的外部索引 |

只投影项目路径，不读取会话正文、登录信息或授权数据库。读取有大小、条数、查询预算限制；索引异常时显示提示而不阻塞全部列表。跨 agent 相同路径合并，所选 agent 的目录优先展示，也可明确选择其他来源。

## 隔离与历史

新建/已有目录使用跨进程 OS 文件锁，从准备直到生成快照结束；同路径或父子目录不能同时派工，兄弟目录允许并行。进程退出后 OS 释放锁，不靠时间猜测解锁。这个锁只协调派工台，不能约束用户手动打开的编辑器或原生 agent。

外部 CLI 的本次运行数据放在运行记录的 `runtime`，不在原项目下新增私有运行目录。保留现有 Codex 工作目录写入沙箱及所需厂商状态根目录；它不是凭据读取或网络目的地隔离。

快照使用普通文件复制，拒绝符号链接/重解析点，前后校验源与目标哈希。跳过已知凭据文件、缓存、依赖目录与 `.git` 等内部数据，保留 `build/dist/out/target` 中的正常产物。资源限额：10,000 文件，512 MiB 总量，64 MiB 单文件，40 层目录，20,000 个扫描条目；超限需整理任务范围后重新派工。

旧版运行的执行目录与验收目录相同。首次复用它前，将旧产物复制到该旧运行的 `artifact-archive`，校验原产物哈希后固定 `artifact_root`。旧批准与结果不被重写；历史预览、下载和待批准检查改读归档。冻结快照禁止再作为执行目录。

原地执行没有自动回滚：失败之前已产生的真实文件修改会留在原目录，页面显示失败原因；不得把失败快照或残留文件当作审核通过。源码仓库宜自行保留版本记录。
