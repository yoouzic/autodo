# WorkBuddy 与豆包桌面会话待命

配置对应桌面 MCP 后，专用会话在实际调用等待工具时才会显示就绪。关闭会话、等待超时或断线后，可在客户端重新开启待命。

普通会话加载连接器、列出工具和空闲心跳都不连接派工台，也不占用派工名额；派工台尚未启动时，这些初始化操作仍可成功。只有专用会话明确调用 `wait_for_task` 才申请对应 provider 的独占连接。已有专用会话占用时，新调用返回 `worker_already_connected`，不会抢占或取消已有任务。

进入过派工等待的会话仍保持专用连接，用于领取后的文件操作与后续等待。需要更换专用会话时，应先结束旧会话的连接器；普通聊天不要复用派工会话。已激活连接遇到桥接重启或失联仍按原规则停止，不自动跨重启续接或重放读写。尚未激活的普通会话可以继续列出工具，等用户明确开始派工时再连接。


## WorkBuddy

确认自定义连接器 `todo-dispatcher` 已启用，在专用新会话发送：

```text
进入派工台正式待命。发现 todo-dispatcher 连接器，用空参数 {} 调用 wait_for_task，不添加 timeout 参数。收到任务后，仅通过该连接器的 read_file、write_file、list_files、publish_result，在租约虚拟工作区内处理可完成的文本文件任务；write_file 使用 text_format="framed" 保留换行，回读后提交真实结果。超出工具能力则提交 needs_input。提交成功后继续等待下一项。禁止原生文件工具、终端、网络、其他连接器、直接操作滴答或输出租约令牌。idle_timeout、取消或错误时停止，不自动重连或创建定时任务。
```

## 豆包

进入 **插件·技能·伙伴 → 插件 → 管理 → todo-dispatcher-doubao**。若显示“运行失败”，点 **重新启动**；启用开关不能作为重建成功的依据。在新的专用工作任务中，通过输入框下方“插件”或 `/`、`@` 选中它，发送：

```text
进入派工台正式待命。仅使用 todo-dispatcher-doubao 连接器，空参数调用 wait_for_task；返回 idle_continue 就立即串行再调用同一工具，保持同一会话。收到任务后，只在本次租约虚拟工作区内处理文本文件，用 read_file、write_file（text_format="framed"）、list_files 和 publish_result，回读并提交真实结果；提交成功后继续等待下一项。超出工具能力则提交 needs_input。禁止原生文件工具、终端、网络、其他连接器、直接操作滴答或输出租约令牌。idle_timeout、取消或任何错误时停止，不自动重连或创建定时任务。
```

豆包每段最多等 40 秒，段间需在 15 秒内续接；同一连接的闲置窗口默认最多 15 分钟、24 段，间隔也计入总预算。过期后需本人重新开启；分段续等会增加工具调用轮次。收到任务并成功提交后可开启下一等待窗口。

## 派工与复审

1. 派工台显示对应 agent 已就绪后，选择默认或新建工作区并分配任务。
2. agent 提交文件后，调度器读取实际产物，交给独立 Codex 验收。
3. 验收通过进入待复审。本人点通过后，才完成对应滴答任务。

目前这两条桌面链路仅提供受限文本文件工具，不提供终端、网络或二进制生成；已有目录原地修改暂不支持。模型和思考强度由客户端会话选择，派工台会拒绝不支持的覆盖设置。连接器的限制只覆盖自身工具，不能视为整个桌面应用的操作系统沙箱。

即使配置了 Windows 登录自启，仍需在桌面客户端手动开启专用会话。安装与配置见 [桌面 MCP 适配](desktop-worker-adapters-2026-11-08.md)。
