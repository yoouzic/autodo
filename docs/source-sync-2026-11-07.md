# 滴答任务状态同步

同步先读取未完成任务。已知任务从列表消失时，AuToDo 查询其详情并核对项目和任务 ID。

## 同步规则

- 默认 `poll_seconds` 为 20 秒。未完成列表保持现有读取路径，缺失本地任务补查明确状态与 projectId/taskId；未知、超时、404、身份错误都保留旧状态并提示未确认。
- 每轮额外探测最多 20 项、6 秒预算；失败按 20/40/80/160/300 秒退避。成功且仍活跃的缺失项也保留最近探测排序，避免列表前缀占满预算、后续完成项永远得不到核对。手动同步可跳过退避。
- 源状态单独记录在 `source_status` 和 `source_checked_at`。旧库只从 payload 回填历史状态，checked_at 保持 NULL；旧 done 记录若缺实时确认，仅做一次详情核对，不周期性重查所有已完成任务。
- 外部完成进入 cancelled+paused，前端独立投影为“滴答已完成”；不生成 agent complete、不自动批准、不调用外部完成接口。原 payload/fingerprint/current_run_id/result/文件保留，旧复审失效。
- 源重新打开后暂停仍保留，直到明确重新分配。旧 worker 的成功/失败回调、旧批准以及撤回操作不能让取消的委派复活。
- 已批准且内容完全匹配的完成回执仍可确认本地 done，并记录真实源状态；完成且内容被编辑不能借用旧验收结论。自身成功回写也记录完成状态，后续重新打开可被检测。

整轮同步还包括清单读取时间；不承诺实时推送或六秒内完成所有网络请求。暂未确认项不会伪装为最新已完成数据。人工复审、账号权限、沙箱和远程登录边界保持。
